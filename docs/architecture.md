# SMART AQI — System Architecture

_Phase 2 deliverable. Companion: `docs/dataset.md` (data audit & strategy).
Status: draft for approval. No application code written yet._

---

## 1. Principles

1. **No fabricated data.** No `Math.random()` AQI, no invented districts, no
   synthetic weather, no placeholder "N/A" cards where real data exists. Where a
   measurement or a geographic level genuinely does not exist, it is `null` and
   the UI hides it or states the limitation.
2. **Provenance on every record** (`source` field) and a data-quality report
   regenerated by the pipeline.
3. **Phase order** (audit → architecture → data → ML → API → auth → UI). Build
   the data and model spine before screens.
4. **Secrets never reach the browser.** Mongo URI, JWT secret, and the
   data.gov.in key live in `backend/.env`; the frontend only ever talks to the
   Flask API.

## 4. Data model (MongoDB, local)

Database `smart_aqi`. Collections:

| Collection | Purpose | Key fields | Indexes |
|---|---|---|---|
| `users` | auth | `email` (unique), `name`, `password_hash` (bcrypt), `created_at` | unique `email` |
| `locations` | the geographic tree actually backed by data | `state`, `district`, `city`, `station_id`, `lat`, `lon`, `has_history` (bool), `history_start/end`, `sources[]` | `state`, `{state,district}`, `{state,district,city}`, unique `station_id` (sparse) |
| `aqi_records` | cleaned historical + appended live snapshots | canonical schema (`docs/dataset.md` §4) | `{state,district,date}`, `{station_id,date}`, `{city,date}`, `date` |
| `forecast_records` | generated 7-day forecasts | `state,district,city,station_id`, `forecast_date`, `model`, `predicted_AQI`, `AQI_bucket`, `lower/upper` (interval), `generated_at`, `horizon_day` (1–7) | `{state,district,generated_at}`, `{station_id,forecast_date}` |
| `model_metrics` | evaluation table | `model_name`, `MAE`, `RMSE`, `R2`, `MAPE`, `training_time_s`, `n_train/val/test`, `split`, `is_best`, `training_date`, `feature_importance?` | `model_name`, `training_date` |
| `health_advisories` | advisory rule content (not per-user) | `aqi_bucket`, `audience`, `headline`, `guidance[]`, `severity` | `{aqi_bucket,audience}` |

`seed_database.py` upserts on natural keys (idempotent, safe to re-run).
`aqi_records` for `station_hour` is large (~2 M rows) — seed the **daily**
grain into Mongo for the app; keep hourly in `data/processed/` for ML only,
unless the user wants hourly served.

## 5. Backend REST API

Base `/api`. All responses `{ "ok": true, "data": … }` or
`{ "ok": false, "error": { "code", "message" } }`. Protected routes require
`Authorization: Bearer <jwt>`.

| Method & path | Auth | Returns |
|---|---|---|
| `POST /auth/register` | – | `{ token, user }` — validates name/email/password strength |
| `POST /auth/login` | – | `{ token, user }` |
| `GET  /auth/me` | ✔ | current user |
| `GET  /states` | ✔ | states present in `locations` |
| `GET  /states/:state/districts` | ✔ | districts with data for that state |
| `GET  /states/:state/overview` | ✔ | state rollup: avg/current AQI, district & station counts, AQI distribution, monthly trend, best/worst districts |
| `GET  /districts/:state/:district/locations` | ✔ | cities/stations under a district |
| `GET  /aqi/current/:state/:district` | ✔ | latest reading (live CPCB if fresh, else latest historical — response says which via `as_of` + `source`) |
| `GET  /aqi/history/:state/:district?from=&to=&grain=` | ✔ | time series |
| `GET  /aqi/forecast/:state/:district?model=` | ✔ | 7-day forecast rows, `model` defaults to best; `is_prediction:true` |
| `GET  /pollutants/:state/:district` | ✔ | current + trend per pollutant |
| `GET  /weather/:state/:district` | ✔ | Open-Meteo current + 7-day (only if location geolocated) |
| `GET  /health-advisory/:state/:district` | ✔ | advisory cards from current + forecast AQI |
| `GET  /model-metrics` | ✔ | `model_metrics` table + which is best |
| `GET  /model-insights/:model?state=&district=` | ✔ | actual-vs-predicted on test set, error series, feature importance |
| `GET  /dashboard/:state/:district` | ✔ | composite payload (current + short history + forecast + advisory) to hydrate the dashboard in one call |

Cross-cutting: Flask-CORS locked to `FRONTEND_URL`; per-route input validation
in `utils/validation.py`; consistent error codes; rate-limit auth routes;
structured logging.

## 6. Authentication

- Registration: name, email (unique, format-checked), password (min length +
  complexity), confirm-password checked client-side and server-side.
- `bcrypt` hash (cost 12) stored in `users.password_hash`; plaintext never
  stored or logged.
- JWT (HS256) signed with `JWT_SECRET`, ~24 h expiry, `sub = user_id`.
  Frontend stores it in memory + `localStorage` fallback; `AuthContext`
  attaches it via an Axios interceptor; 401 → redirect to `/login`.
- "Forgot password" screen exists; v1 does a simple token reset stub (no email
  provider assumed) — flagged in `docs/api.md`.

## 7. ML pipeline

Detailed in `docs/ml_pipeline.md` / `docs/forecasting.md`; summary:

- **Target:** next-day AQI (and recursively out to +7). AQI is modelled
  directly (present, CPCB-scaled, already in data).
- **Grain:** pooled multi-station **panel** (recommended station-hour or
  station-day — see `dataset.md` §6 decision 1). One model per architecture
  across all stations, with station/location features, not one model per city.
- **Chronological split, no shuffling:** train ≤ 2019-06-30, val
  2019-07-01…2019-12-31, test 2020-01-01…2020-07-01 (≈70/15/15 by time).
  Scalers fit on train only. Documented in `model_metrics.split`.
- **Features:** `lag_1,2,3,7`; `rolling_mean_3/7`, `rolling_std_7`;
  `day_of_week`, `month`, `season`; pollutant levels & justified ratios;
  Open-Meteo weather if decision favours it; station embedding / one-hot.
- **Sequence models:** input window 14–30 steps → next step. LSTM (2×LSTM +
  dropout + dense), GRU (mirrored), Transformer (learned positional encoding +
  multi-head attention + FFN + norm + regression head — a real attention model,
  not a renamed MLP). Early stopping, LR scheduling, checkpointing.
- **Baseline:** XGBoost on the engineered tabular features (RandomForest
  fallback if XGBoost unavailable). Provides feature importance.
- **Ensemble:** stacking regressor over the 4 base predictions (kept only if it
  beats the best single model on validation).
- **Selection:** best model chosen by lowest validation MAE (tie-break RMSE);
  `is_best` written to `model_metrics` — never hard-coded.
- **7-day forecast:** recursive multi-step; predicted AQI fed back as the new
  lag, calendar features advanced, weather from Open-Meteo forecast where
  available. Uncertainty band from test-residual quantiles per horizon (and MC
  dropout for the NN where feasible). Every forecast row `is_prediction:true`.
- **Coverage guard:** a location gets a forecast only if it has an unbroken
  recent window ≥ the model's input length. Otherwise the API returns
  `forecast_available:false` with a reason; the UI shows an explanatory state,
  not numbers.

## 9. 3D visualisation architecture

One `<Canvas>` per view, lazy-loaded (`React.lazy` + Suspense), DPR-capped,
`frameloop="demand"` where static, full geometry/material/texture disposal on
unmount, particle counts scaled to viewport and capped.

| Component | Where | What it shows (real data) |
|---|---|---|
| `<AtmosphereSphere>` | Landing hero, Login | GPU particle shell; particle density & colour driven by a representative AQI value; subtle pointer parallax. |
| `<IndiaMap3D>` | Dashboard, District Explorer | Extruded state/district polygons from geoBoundaries; height/colour = latest AQI; hover & click → detail panel. Only regions with data are interactive. |
| `<PollutantColumns>` | Pollutant Analysis | 3D bars: X = pollutant, Y = concentration, Z = time or nearby stations; animated transitions on district/date change; hover tooltips. |
| `<ForecastSurface>` | Forecast page | Surface/ribbon: X = day 1–7, Y = predicted AQI, Z = model or uncertainty band; legend; orbit controls. |

2D (Recharts) is used where it communicates better: AQI history line, forecast
line with CI band, pollutant trends, model comparison bars, actual-vs-predicted
scatter, district comparison.

## 10. Frontend design system

- **Aesthetic:** dark, premium, futuristic. Tokens in `styles/tokens.css`:
  bg `#050507`/`#08080D`, purple `#6D28D9`/`#7C3AED`, violet `#8B5CF6`, accent
  `#A78BFA`, text `#FFFFFF`/`#D4D4D8`/`#A1A1AA`. AQI category colours follow the
  CPCB palette and are semantic (not the brand purple).
- **CSS only** — hand-written, one stylesheet per component, CSS variables,
  `@media` for responsive (desktop → mobile). **No Tailwind, no CSS framework.**
- Motion: GSAP + Framer Motion for reveals, staggered text, scroll triggers,
  magnetic buttons, page transitions, animated counters — used sparingly.
- Glassmorphism (backdrop-blur panels) used selectively.
- Accessibility: keyboard nav, focus states, labelled controls, adequate
  contrast, `prefers-reduced-motion` respected by all animations and 3D.
- Loading screen: "SMART AQI — Mapping the air around you…" with the atmosphere
  particles, then transition into the app.
- Errors: toast notifications + inline validation, no browser `alert()`.

Landing sections: Hero (3D) · Why SMART AQI · Live AQI intelligence · 3D
showcase · 7-day forecasting · AI model comparison · Health advisory · District
intelligence · Technology · Final CTA · Footer.
